
面向「设计师口头表达其设计过程的文本」，标注 7 个标签。本说明的规则与例子全部取自已定稿的五人语料。  
无需设计学或哲学背景，照本说明即可标。

---

## 一、七个标签

先分两问：**这句在”移动”，还是”停在原地”？**

**四个移动标签**（从一个空间到另一个空间，或在一个空间内推进）：

|标|一句话|通俗理解|
|---|---|---|
|**C→K**|有想法，去求证|已有一个概念/方案，去查数据、问用户、要解释，**从不确定走向确定**|
|**K→C**|由已知，得想法|根据已知条件/数据，**推导出**自己的概念或方案|
|**C→C**|改想法|在已有的概念/方案上**细化、调整、加减**|
|**K→K**|想已知|在已知范围内**推理、推导后果**，不产出新概念|

**三个静态标签**（只是停在某处，没有移动）：

|标|一句话|通俗理解|
|---|---|---|
|**K**|说已知|陈述已知信息，或**把一个假设当成已知**来讲|
|**C**|提想法|提出一个**待实现、不确定**的概念，只是”认为可以”|
|**V**|表态度|表述**观点/态度/原则/立场/方法论准则**——评判尺子，不指向具体待造之物|

---

## 二、每个标签的判定 + 语料实例

### C→K　有想法，去求证

**判据**：已经有一个概念/方案，希望通过用户、市场、数据、他人解释等**外部知识**来确定它。

- 「主要用户群体是什么？……老年人是否还愿意来？是否影响营收？这些是需要调研的。」
- 「快速出小型可验证的思维实验，请目标用户来做测试，看他们真实的反馈」
- 「上层如何说服我……这个问题我确实需要一个解释。」（求解释也算求证）

### K→C　由已知，得想法

**判据**：根据已知条件/数据，**推出**一个自己的概念、目标或方案。

- 「明确自己的设计目标……就是提高收益。」（由已知商业条件得出目标）
- 「如果有影响，我会基于这些访谈与数据，去对现有方案优化和迭代」（迭代出的概念由前面的 K 确定）
- 「零售行业完全可以面向不同的人群，做不同的划分。」（由已知零售分众推出概念）
- 「将技术应用到那些让用户无法解决的问题……不那么顺畅的节点。」（由已知用户痛点推出技术方案）

### C→C　改想法

**判据**：在**已有的概念/方案**上做细化、调整、加减属性（含把已知结果用于调方案）。

- 「保留一部分人工的收银台，或者提供志愿服务、操作指南」（现有概念下细化）
- 「全改无人会影响收益。所以推荐保留 1到2个人工收银。」（把已知结果用于调方案）
- 「效益应该适度向效率让步」（减弱方案的某属性）
- 「诱导……我们也可以是引导」（重新界定方案里的概念）

### K→K　想已知

**判据**：在已知内推理、推导后果，不产出新概念。

- 「如果我能看到各部门数据……那我其实当的是老板。」（归谬）
- 「牺牲用户去转短期收益，那迟早也会崩盘。」（推理后果）
- 「用户反感算法……会影响长远收益。」（推导感受与收益）

### K　说已知

**判据**：陈述已知信息，或把假设当已知。

- 「通过调研可知，该社区老年人较多」
- 「老年人多，改成无人的以后他们就不来了」（把假设当已知）
- 「商业要求……是我第一时间假设成立的一个内容」

### C　提想法

**判据**：提出一个待实现、不确定的概念，只是”认为可以”；或持有一个方案概念。

- 「三个因素并不矛盾，通过设计能够进行有效权衡。」（只是认为可以权衡）
- 「社区超市……应该是要让顾客逛得舒服省心」（指向一个待造的超市方案）
- 「我会非常愿意去尝试做数字化方案的铺开。」（持有并愿推进 C₀）
- 「完全是可以共存的。」（认为可共存，不确定的概念）

### V　表态度

**判据**：表述观点/态度/原则/立场/方法论准则，**不指向具体待造之物**。

- 「我觉得这没什么……很正常的事情。」（我觉得，观点类）
- 「调用现有资源，以比较小的代价去调整。」（方法论原则）
- 「尊重用户才能走得更远」「设计存在的本质是为人们提供更好的体验」（价值原则）
- 「设计部门不承担其他部门责任」（职责立场）

## 三、三条最关键的分界（标错最多的地方）

### 分界一：V 还是 C？——**“应该”句怎么标**

很多句子带”应该/应”，容易全标 V。**测试：这句指向一个可造之物吗？**

- 指向一个待实现、能被细化/验证的**对象**（一个超市、一个方案、一种界面）→ **C**（或 C→C / K→C）。
- 只在讲”什么是好的/对的”，**无待造对象** → **V**。

|句子|标|为什么|
|---|---|---|
|社区超市**应该**让顾客逛得舒服省心|**C**|指向一个待造的超市方案，重心在那个超市|
|尊重用户才能走得更远|**V**|评判尺子，无待造对象|
|设计本质**应**是提供更好体验|**V**|讲设计该是什么，无具体方案|

**延伸**：一条原则**一旦落到具体机制/约束**（“留一个选择空间”“设一个引导式界面”），就从 V 变 **C→C**；停在抽象层（“应当尊重”“应当可引导”）→ 仍 V。

### 分界二：C→K 还是 K→C？——**求证 vs 推导**

- **C→K**：已有想法，**向外求**知识来确定它（问、查、测）。方向是”想法 → 求确认”。
- **K→C**：已有知识，**向内推**出一个想法。方向是”已知 → 得概念”。

|句子|标|
|---|---|
|我会去调研验证这个方案是否真能提高收益|**C→K**（求证）|
|基于访谈数据去优化迭代方案|**K→C**（由数据推出新方案）|

### 分界三：C→C 还是 K→C？——**改旧方案 vs 推新概念**

- **C→C**：在**已存在**的概念/方案上加减细化。
- **K→C**：**新推出**一个概念（此前没有）。

|句子|标|
|---|---|
|保留人工收银 + 志愿服务（对现有方案加属性）|**C→C**|
|老年客户另建一套传统模式商超（新推出方案）|视语境 C→C / K→C|

## 四、易混词提醒（判词无用，判功能）

|表面|别被骗|看什么|
|---|---|---|
|「调研/研究」|不一定是 C→K|求证概念能否成立=C→K；为拆分/推导概念取信息=另判|
|「应该/应」|不一定是 V|指向可造之物=C 系；只讲对错=V|
|「我觉得/我认为」|常是 V|但若后接一个待造方案，则看方案=C 系|
|「本来就是/一定」|常是 K 或 V|陈述事实=K；断言价值立场=V|

## 五、切分单元的规则

**单元 = 一个动作，呈现为该动作对应的完整原文（可跨句号）。**

- **合并**：连续几句若是**同一个动作**（同一概念、同一方向），并成一个单元。  
    例：四个连续追问 + “这些需要调研” → 合并为一个 **C→K**。
- **不合并**：一句里若含**方向不同的两个动作**（如先减一个属性、再加一个属性），或换了概念、换了方向 → 切开。
- **一句含主次两动作**：取**主导动作**定标，次要动作在理由列括注。  
    例：「尊重用户才能走得更远，社区超市应让顾客舒服省心」→ 主导是方案概念 **C**，“尊重用户”半句的 V 在注里说明。

## 六、标注流程（每个单元）

```
1. 先定动作边界：这段连续原文是不是"一个动作"？是→合为一个单元。
2. 有没有移动？
   有移动 → C→K / K→C / C→C / K→K（按方向）
   没移动、停在原地 → K / C / V
3. 若像 V：做"可造之物"测试 → 指向待造对象则改 C 系。
4. 若像 C→K：确认方向是"向外求证"而非"由已知推出（K→C）"。
5. 写理由（一句话，说清为什么是这个标）。
```

## 七、五人语料的整体画像（供标注员校准预期）

不同设计师的标签分布差异很大，这是正常的，反映其应对困境的方式：

- **务实调研派**：**C→K + C→C** 为主——不断求证、动手改方案。
- **职责边界派**：**V** 为主——几乎只在表态、划职责立场，很少产出方案。
- **人本情感派**：**V** 为主——价值密集，偶有由痛点推出的 K→C。
- **兴奋福祉派**：**V + C→K**——价值表态 + 求证。
- **对齐公司派**：**C→C + V**——逐条改方案 + 立场表态。

**含义**：面对伦理困境，多数人主要在”表态（V）“，只有务实型显著地在做”求证 + 改方案”的设计推理。标注时不必强求每人都均匀分布——**V 多不是标错，是这类语料的特征**。

## 八、信度提示

- **双人独立标 + 分歧仲裁**：分歧最集中在”V vs C（应该句）“和”C→K vs K→C（求证 vs 推导）“两处，仲裁先查这两条。
- **三处需项目统一口径**（组内先约定，避免各标各的）：
    1. 由**价值**推出的概念算 C 还是由**已知需求**推出算 K→C；
    2. 原则**落到具体机制**算 V 还是 C→C；
    3. **预测句**（“大家会愉快接纳”）算 K 还是 K→K。
- 每个标注员上岗前，先独立标设计师1（务实调研派）全段，与本说明第二节的实例核对，一致后再标其余。
