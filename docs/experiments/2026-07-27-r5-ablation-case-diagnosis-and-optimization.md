# R5 消融案例诊断与 Prompt 优化建议

## 1. 结论

当前结果不是模型完全忽略个体条件，而是三类信号在不同层面起作用：

1. active4 能改变价值优先级，但经常被同任务 Q7 ICL 的群体默认方案覆盖；
2. Q2 主要增加序列长度和组合差异，没有稳定提升 Q7 个体匹配；
3. rules 能控制状态转移，但现有探索性规则没有稳定转化为正确的 Q7 个体语义。

因此，当前最主要的问题是同任务 ICL 的内容锚定，其次是 Q2 的跨情境噪声，
最后才是规则是否被模型执行。

## 2. 全体诊断证据

### 2.1 Q7 ICL 形成了几乎固定的群体锚点

- 159/162 个目标使用完全相同的三个 Q7 示例：D044、D119、D120。
- 完整方法中，83/162 个回答写入了示例中的“中年家庭主妇”，80/162
  写入“年轻上班族”；这些并非 Q7 题干事实。
- 158/162 个回答提出保留人工服务或人工协助。
- 150/162 个回答使用“平衡”或“兼顾”的折中叙事。

因此，132 条 unique state sequences 并不等价于 132 种个体决策。状态排列具有
多样性，但语义方案仍高度坍缩到“保留人工 + 算法透明 + 用户测试”的群体模板。

### 2.2 模型确实执行了规则，但规则没有带来正确个体语义

按照每位参与者被注入的三个规则，检查预测序列是否包含对应转移或目标状态：

| 输出条件 | 对目标本人规则的命中率 | 对 shuffled donor 规则的命中率 |
|---|---:|---:|
| Ours | 0.471 | 0.414 |
| Ours w/o rules | 0.374 | 0.383 |
| Ours w/ shuffled rules | 0.434 | 0.479 |

正确 rules 相对 no-rules 将本人规则命中率提高约 9.7 个百分点；shuffled
condition 则更符合错误 donor 的规则。这证明 Prompt uptake 存在。下游指标没有
改善，原因在于规则本身只规定操作转移，不能决定关注什么、采取什么底线。

此外，冻结库中的 90 条规则均为 exploratory candidates：没有规则达到
FDR \(q\le .05\)，freeze manifest 中 `validated_rule_count=0`。当前结果不能被
解释为已验证的个体心理规律。

### 2.3 Q2 增加结构变化，但作用很弱且跨情境

| 条件 | 平均状态数 | 与本人 Q2 的 NES | 预测 bigram 出现在本人 Q2 的比例 |
|---|---:|---:|---:|
| Ours | 8.35 | 0.2670 | 0.1681 |
| Ours w/o Q2 | 7.55 | 0.2543 | 0.1511 |

Q2 使回答平均增加约 0.8 个状态，但对本人 Q2 结构的增量很小。它更像是让模型
展开更多步骤，而不是稳定复现该参与者的跨情境推理风格。这解释了 no-Q2 的
LenErr 和部分价值指标更好，而 Unique、KCDR 和 TopShare 变差。

## 3. 配对案例

### 3.1 D001：active4 被读取，但最终底线仍被群体模板覆盖

D001 的 active4 明确包含：

- 尽早整合新技术；
- 愿意承担创新初期的转化损失；
- 公司危机下可一定程度接受成瘾性交互；
- 多数用户效率优先于边缘群体的额外无障碍要求。

Ours 的开头确实体现了这一差异：“商业要求在设计过程中具有很高的优先级”，
随后先提出整合自助结账柱和 AI 货架。去掉 active4 后，回答改为“优先考虑社区
服务的包容性和伦理底线”。这说明 active4 有局部因果作用。

但两种条件最终都收敛到保留人工触点、优化自助界面和取得平衡。换言之，
active4 改变了论证开头，却没有改变最终方案边界。其原因是三个 Q7 ICL 都提供
了强烈的折中式内容锚点。

### 3.2 D001：rules 改变了转移，却没有改变方案

D001 的单维规则为 \(K{\to}C\rightarrow K\)。Ours 的序列包含：

```text
K -> KtoC -> K -> KtoK -> ...
```

而 no-rules 为：

```text
K -> KtoK -> KtoK -> KtoC -> ...
```

规则被准确执行。然而两者都生成“保留人工服务 + 优化算法透明度 + 用户测试”
的兼容方案。当前规则改变的是标签路径，不是个体化决策内容。

### 3.3 D001：shuffled rules 也会被模型忠实执行

shuffled condition 使用 D161 的规则，并生成三个连续 KtoK 后再转入 KtoC。
它与正确规则版本的状态路径明显不同，但自然语言仍然是相同的折中方案。
这正是 shuffled-rules 的 KCDR 不差、但无法证明个体匹配的原因。

### 3.4 D003 与 D011：不同画像仍落入相同语义方案

D003 的 matched rule 与弱势群体优先有关，Ours 确实强调老年群体、测试使用
频率并保留人工收银；但 no-active4、no-rules 和 shuffled-rules 也提出几乎相同
方案。D011 在多个条件中反复输出“人本数字化”“保留人工触点”“算法透明化”。
这里的共同语义主要来自 Q7 示例和模型默认伦理回答，而不是个体画像。

## 4. 代码与 Prompt 层面的具体原因

### 4.1 ICL 选择只追求状态覆盖

当前 `select_coverage_examples` 几乎为所有人选择同一组三个示例。示例包含完整
Q7 事实扩写、立场和方案，即使 Prompt 写了“不得复制”，模型仍然会内容迁移。

### 4.2 rule selector 没有真正进行 Q7 语义适用性过滤

运行时 `select_routes` 根据画像触发强度和 held-out loss 选择规则，但没有使用
Q7 文本计算 semantic relevance。Q3--Q6 contextual rule 仅限制来源问题为 Q4/Q6，
不等于它与 Q7 的冲突语义匹配。这与论文所写的“按冲突情境过滤”不一致。

### 4.3 三条规则主要规定状态，不规定个体关注对象

162 人中 contextual rule 有 112 次要求增加 KtoC；另有 82 次关系规则要求
CtoK 后进入 KtoC。大量规则共同推动“再提出一个方案”，但没有规定新方案应当
更偏效率、包容、透明度还是商业底线，因此容易回到语言模型的平均折中答案。

### 4.4 输出缺少软长度预算

Ours 平均生成 8.35 个状态、约 562 个中文字符。拆分要求会促使模型把三个困境
逐项展开，再机械补充风险、方案、细化和验证，造成 LenErr 偏高和固定流程化。

## 5. 最小可行优化

### 5.1 第一优先级：移除同任务 Q7 自然语言 ICL

推荐直接取消三条完整 Q7 reasoning-response examples。系统 Prompt 已经包含
K/KtoK、KtoK/KtoC、CtoK/CtoC 的边界反例，足以说明状态语义。

若必须保留格式 ICL，只保留一个与 Q7 无关的合成微型示例：

```json
{"units":[
  {"state":"KtoK","text":"由已知期限推导风险。"},
  {"state":"KtoC","text":"由该风险推出一个候选方向。"}
]}
```

不得提供其他设计师的 PI、完整 Q7 文本、立场、方案或状态序列。这样既保留
one-call 格式示范，又消除同任务答案泄漏和群体方案锚定。

### 5.2 第二优先级：把 active4 写成“相对人群的决策偏移”

当前线索只写一般倾向，模型容易将其软化为平衡表述。建议改成：

```text
# 目标设计师相对人群的决策偏移
- 相比一般设计师，此人更可能优先……
- 因此在本题中，更可能先牺牲/保留……，但不得违背公开事实。
- 不要默认生成兼顾所有人的折中方案；只有当这些个人线索支持折中时才折中。
```

并增加一条合同：

```text
至少一个单元必须让目标设计师的个人优先级实际改变取舍顺序、方案边界或验证重点，
而不只是复述价值词。
```

### 5.3 第三优先级：压缩 Q2 为行为摘要

不再注入完整 Q2 情境和原回答。保留：

1. 本人 Q2 状态序列；
2. 起始方式、常用转移和验证/细化频率；
3. 一句不含旧任务事实或方案的关注方式摘要。

例如：

```text
本人跨任务行为记忆：通常先形成方向，再多次验证和细化；倾向在收敛前补充现实约束。
这是组织方式，不是本题方案，也不要求复制原序列。
```

### 5.4 第四优先级：规则从“三条固定注入”改为“一条适用规则”

运行时只保留一条满足以下条件的规则：

- 画像触发成立；
- source state 在自然序列中可达；
- 与 Q7 冲突语义相关；
- 不与 active4 的决策方向冲突；
- held-out improvement 为正且在多数 folds 改善。

Q3--Q6 contextual rule 只有在其原冲突与 Q7 明确匹配时才使用。规则文本同时说明
其本题语义目的，例如：

```text
若自然出现 CtoK，则下一步优先用 KtoC 把用户测试结果转化为本题方案边界；
不要为了使用规则而强行插入 CtoK。
```

### 5.5 第五优先级：加入 5--7 个单元的软预算

```text
通常使用 5--7 个单元完成本段；只有存在新的独立操作时才增加。
不要为三个困境分别机械生成“风险—方案—测试”。
```

这是软预算，不是固定模板，可降低当前平均 8.35 状态导致的 LenErr。

## 6. 推荐的新一轮最小实验

如果只能再做一个小规模 pilot，建议 10--20 人、同一 GPT-4o seed，比较：

| 条件 | Q7 NL ICL | Q2 | active4 | rules |
|---|---|---|---|---|
| Current | 3 条完整 | 完整 | 原表述 | 3 条 |
| R6-base | 无/合成微例 | 行为摘要 | 相对偏移 | 无 |
| R6-rule | 无/合成微例 | 行为摘要 | 相对偏移 | 1 条语义适用规则 |
| R6-shuffled | 同上 | 同上 | 同上 | 错配的 1 条规则 |

验收顺序应为：

1. Q7 示例事实泄漏显著下降；
2. “保留人工 + 平衡”方案占比下降；
3. active4 matched-minus-no-active4 的 own-profile advantage 增大；
4. matched rule compliance 高于 shuffled-rule compliance；
5. KC-NES 和 LenErr 不因个体化增强而明显恶化。

## 7. 论文表述边界

在未进行上述优化前，可以主张：

- active4 改善价值画像对齐；
- Q2 保留部分群体层面的轨迹差异；
- rules 能改变生成操作路径。

不能主张：

- 三个组件均全面提升个体化；
- 当前 rules 已被验证为个体心理规律；
- Unique/KCDR 单独证明了个体化；
- 当前 Q7 ICL 只校准格式而没有迁移内容。
