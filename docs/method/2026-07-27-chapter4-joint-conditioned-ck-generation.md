# 第四章　画像、规则与记忆条件下的 C-K 轨迹联合生成

本章回答如下问题：在获得可解释的个体画像与可标注的 C-K 表示后，如何生成既体现个体差异、又能被独立审计的设计决策过程？与将人口信息、价值描述和示例简单拼接为“角色设定”的做法不同，我们把方法定义为一个**模块化条件生成问题**：人口与职业背景（PI）、30 维价值画像（V30）、目标设计者的跨情境历史、冻结的认知操作规则以及对照式检索示例分别构成可启用或关闭的条件通道；冻结语言模型先生成结构化 C-K 轨迹，再在同一聊天上下文中根据该轨迹生成第一人称回答。

这一设计有两个直接目的。第一，生成文本之外同时暴露有限状态序列，使“是否模拟了该设计者的思考方式”可以在轨迹层面检验，而不只依赖文本相似度或主观流畅度。第二，各条件通道均有确定的数据来源和消融边界，从而可以区分画像、规则和记忆示例的贡献。这里的 C-K 序列是对可观察认知操作的结构化摘要，不是模型隐藏思维链的转录。

## 4.1 Task Definition

### 4.1.1 输入、输出与状态空间

设设计者集合为 \(\mathcal U\)，目标设计者为 \(i\)，待回答的公开设计情境及段落任务为 \(X^\ast\)。方法使用以下条件：

\[
Z_i=(P_i,V_i,H_i,A_i,E_i),
\]

其中，\(P_i\) 为 PI 人口与职业背景；\(V_i\in\{1,\ldots,6\}^{30}\) 为 V30；\(H_i\) 为目标设计者完整的 Q2 跨情境记录；\(A_i\) 为根据 \(V_i\) 和当前任务从冻结规则库路由得到的软操作指令；\(E_i\) 为从其他设计者中检索的上下文示例。模型输出

\[
O_i=(M_i,Y_i),
\]

相应地，跨情境建模数据与目标评测数据分别写为

\[
\mathcal D_{Q2}=\{(P_i,V_i,X^{Q2},M_i^{Q2},Y_i^{Q2})\}_{i\in\mathcal U},
\qquad
\mathcal D_{Q7}^{eval}=\{(P_i,V_i,X_j^{Q7},M_{ij}^{gold},Y_{ij}^{gold})\}_{i,j}.
\]

\(\mathcal D_{Q2}\) 为个人历史、跨用户示例和 Q2 规则提取提供信息；\(\mathcal D_{Q7}^{eval}\) 的使用范围由 inductive/transductive 协议分别约束，详见 4.4.2 节。

其中 \(M_i=(m_1,\ldots,m_T)\) 是结构化 C-K 轨迹，\(Y_i\) 是与该轨迹对应的第一人称自然语言回答。当前生成状态空间固定为

\[
\mathcal S_{KC}=\{K,C,K{\to}C,C{\to}K,K{\to}K,C{\to}C\}.
\]

\(K\) 表示陈述已知事实、经验或约束，\(C\) 表示提出或持有待实现的概念；\(K{\to}C\) 表示由已知条件推出新概念，\(C{\to}K\) 表示对已有概念提出查证、访谈或测试计划，\(K{\to}K\) 表示在已知信息内推演后果而不产生新方案，\(C{\to}C\) 表示细化、调整或替换已有方案。`START` 和 `STOP` 仅用于数据处理中的序列边界，不作为生成标签。

需要特别区分两个同名符号。Q7 人工标注包含七类过程状态

\[
\mathcal S_{gold}=\mathcal S_{KC}\cup\{V\},
\]

其中过程状态 \(V\) 表示态度、原则或价值立场；而 \(V_i\) 或 V30 表示设计者的 30 维画像。二者在语义和计算上均不相同。当前生成本体只预测六类 KC 操作。计算 KC-NES 时，对七状态人工金标使用固定投影 \(\pi_{KC}\)：删除过程状态 `V` 并保持其余状态的相对顺序，即

\[
M^{KC}_{ij}=\pi_{KC}(M^{gold}_{ij}).
\]

因此，KC-NES 衡量的是六状态投影后的轨迹保真度，不等同于完整七状态重建。被删除的价值立场不被视为不存在，而是在自然语言层通过 value faithfulness 单独评价。

### 4.1.2 同上下文两阶段生成目标

给定目标情境和启用的条件通道，第一阶段生成可独立评价的轨迹：

\[
\hat M_i\sim p_{\theta}(M\mid X^\ast,P_i,V_i,H_i,A_i,E_i).
\]

轨迹冻结后，确定性 selector 根据每一步的 position、segment role 和 previous/current/next state 选择动态价值线索 \(D_i(\hat M_i)\)。第二阶段在同一 chat history 中生成与轨迹逐单元对齐的文本：

\[
\hat Y_i\sim p_{\phi}(Y\mid X^\ast,P_i,V_i,H_i,A_i,E_i,\hat M_i,D_i(\hat M_i)).
\]

两个阶段使用同一冻结 Qwen3-8B 快照，但采用阶段分离、目标配对的随机种子。阶段一只返回 `state_sequence`；阶段二一次返回与其等长的 `nl_units` 数组，程序按原顺序直接拼接为 `nl_answer`。该投影不改写内容，也不调用 Composer。

R2 的必要性来自动态条件的可计算性，而不是假定 split 架构天然更优：在轨迹产生之前，transition-aware selector 不知道局部状态。早期 joint-vs-split pilot 的平均性能差异很小，因此本文不把两阶段本身作为贡献；它只是完整复用旧 Realizer 动态 selector、同时保留轨迹可审计性的实现合同。

这里严格约束的是 JSON schema、合法状态和单元数对齐，而不是自然语言句法。每个状态只给出操作语义，不规定连接词、句子数量或固定表达；长度、标点、`CtoC` 前置条件以及语义错位均原样记录，不通过重采样或生成式修复隐藏。

## 4.2 Structured User Context

### 4.2.1 PI：人口与专业背景

\(P_i\) 描述设计者可被公开使用的身份与工作背景，包括身份信息、教育阶段、教育背景、设计经验、设计领域、工作情境、服务对象、项目角色、项目类型和跨学科经历。空字段不进入 Prompt，参与者 ID 不作为模型输入。PI 提供的是角色能力和专业语境，而不是价值偏好的代理变量；因此它与 V30 分开呈现，也不允许模型从 PI 补造未提供的项目经历。

### 4.2.2 V30：静态 Full30 与逐步动态线索

V30 的每一维均为 1--6 的有序分数。我们使用冻结词典将其确定性转换为方向和强度描述，而不是直接向模型暴露量表题号或数值：1 表示强烈倾向反向极，2--3 表示中等倾向反向极，4--5 表示中等倾向正向极，6 表示强烈倾向正向极。完整条件记为

\[
R_{30}(V_i)=\bigl(r_1(v_{i1}),\ldots,r_{30}(v_{i30})\bigr).
\]

V30 通过两个用途不同的通道进入生成。静态通道 \(R_{30}(V_i)\) 在整个上下文中常驻，保留全部 30 维信息。动态通道在轨迹冻结后针对每一步选择 8 条线索：

\[
D_{it}^{(8)}=\operatorname{Top8}_{d\in I^{Q2}}
g\!\left(v_{id},X^\ast,\operatorname{pos}_t,
\operatorname{role}_t,m_{t-1},m_t,m_{t+1}\right),
\]

其中 \(I^{Q2}\) 是旧 Realizer 冻结的 10 维相关候选集，\(g\) 同时使用画像方向、公开任务语义、步骤位置、段落角色和局部状态转移，最终保留 8 条。动态线索只影响对应步骤的关注点与取舍，不决定状态本身。B 仅启用动态通道；C--F 同时启用静态 Full30 和动态 8-cue。因此 `C-B` 检验在动态条件始终存在时，完整静态画像是否提供增量，而不是比较 Full30 与旧 Active4。

### 4.2.3 目标设计者的完整 Q2 历史

目标设计者的跨情境记忆写为

\[
H_i=(X^{Q2},M_i^{Q2},Y_i^{Q2}),
\]

即公开 Q2 情境、完整人工 Q2 状态序列和对应回答。与只压缩为长度或状态频率不同，完整 Q2 同时保留了该设计者过去如何组织认知操作以及如何用语言表达取舍。Prompt 将其明确标为“跨任务记忆”：模型可以迁移稳定的关注方式和表达倾向，但不得复制 Q2 的场景事实、具体方案、固定长度或状态顺序到 Q7。

这一信息通道的作用是提供个人历史，而不是证明 Q2 轨迹可以直接预测 Q7。已有诊断显示，本人 Q2 相对随机他人 Q2 对 Q7 Seg2 的结构预测增量接近零，因此本章不把 \(H_i\) 宣称为已经验证的个体轨迹先验。它是否有用由后续整套上下文比较和专门消融决定。

## 4.3 Frozen Trait-conditioned Rulebank

### 4.3.1 规则提取

直接将 30 个维度全部写入 Prompt 只能告诉模型“此人重视什么”，不能说明画像可能怎样改变认知操作。为建立显式、可审计的画像到 C-K 操作映射，我们在 Q1--Q6 上离线提取规则候选，并在目标 Q7 生成前冻结规则库 \(\mathcal R\)。每条规则统一表示为

\[
r=(g_r(V_i),c_r,a_r,b_r,\eta_r),
\]

其中 \(g_r\) 是画像触发条件，\(c_r\) 是当前状态或题目语境，\(a_r\) 是优先采用的下一 C-K 操作，\(b_r\) 是禁止补造事实等语义 guard，\(\eta_r\) 保存 bootstrap 稳定性和 held-out 增益等证据元数据。

冻结库包含三层。第一层是 12 条 Q2 单维规则：在控制序列位置后，以 L1 正则逻辑回归估计单个 V30 维度对下一状态的条件作用。第二层是 49 条 Q2 双维关系规则：先从 V30 中识别稳定维度对，再以 `synergy`、`tension`、`left/right dominant` 或 `balanced` 等关系谓词建模超出单维主效应的残差作用。第三层是 29 条 Q3--Q6 情境偏好规则，用于描述特定冲突语境下某类认知操作的相对优先级。所有重采样和交叉验证均以参与者为单位；正式提取使用 1,000 次 bootstrap、1,000 次 participant permutation 和五折 participant-held-out 检验。

三层共包含 90 条规则候选，其冻结 SHA-256 分别为 `6c867dadd18631a4b9802415c1c7b3b748c7b261434dffd9e88656e6264189af`、`e8dfa785529ea4aaf7732d5d6d4402180db5709654ca4ec0bd9c447863e70313` 和 `ef4243f35c27c0bdf4fdbd0489c9c0c48345107a5f2cde4f02f714c3383c2b4b`。规则发现与选择不读取 Q7，冻结后不允许依据 Q7 结果增删规则或调整阈值，只允许在消融中启用或关闭完整规则层。

### 4.3.2 画像路由与冲突处理

对于设计者 \(i\)，路由器生成

\[
A_i=\operatorname{Route}(V_i,\mathcal R,X^\ast).
\]

每个启用层最多选择一条满足画像触发条件和场景 guard 的规则。候选首先按画像触发强度排序，再以 participant-held-out loss 增益和固定规则 ID 破除并列。若单维规则与双维规则针对同一来源状态给出冲突偏好，双维关系规则作为对单维主效应的修正而具有软优先级；Q3--Q6 辅助层仅在其预先定义的 Q4/Q6 冲突语义门控下启用。

路由结果被渲染为自然语言软指令，例如“当当前操作为 \(C\) 时，优先转向 \(C{\to}K\)，即提出未来或条件式验证计划”。规则不直接编辑输出序列，也不要求模型机械插入某个状态；与当前场景事实冲突时，以场景为准。特别地，\(C{\to}K\) 只能实现为尚待执行的查证，不能写成“访谈结果表明”等已完成证据；\(K{\to}K\) 只能推演现有信息，不得夹带新方案，新方案必须由 \(C\)、\(K{\to}C\) 或 \(C{\to}C\) 承担。

需要强调，冻结不等于验证。当前三层规则的 `validated_rule_count` 为 0，30 人 pilot 中正确画像路由相对错配画像路由的置信区间仍跨 0。因此本文将其称为**冻结的探索性路由候选**或 soft operational priors，而不称为心理规律或因果规则。它们的价值必须由下游 correct-profile、shuffled-profile 及层级消融检验决定。

## 4.4 Neighbor-Contrasted Memory and Q7 ICL

### 4.4.1 V30 近邻与远邻 Q2

除目标设计者自己的 Q2 历史外，我们从不包含目标设计者的候选池 \(\mathcal U_{-i}\) 中检索其他人的完整 Q2 示例。为避免把“是否提供示例”和“示例是否与画像相近”混为一谈，近邻和远邻条件使用相同示例数、相同字段及相同 token 预算，仅改变示例来源。

首先在冻结检索池上逐维标准化 V30：

\[
\widetilde V_{id}=\frac{V_{id}-\mu_d^{train}}{\sigma_d^{train}},
\qquad
d(i,j)=\|\widetilde V_i-\widetilde V_j\|_2.
\]

最近的 \(k\) 位构成 \(E_i^{near}\)，最远的 \(k\) 位构成 \(E_i^{far}\)。主实现固定 \(k=3\)，与既有 ICL shot 数一致。目标设计者始终被排除；距离并列按冻结的匿名 public ID 顺序处理。每个示例包含示例 PI、公开 Q2 情境、完整 Q2 状态序列和 Q2 回答。示例只用于展示可能的过程组织和表达，不得被当作目标设计者的个人事实。

近邻检索在这里是一个待检验机制，而不是已知有效模块。已有事后分析仅发现近邻相对远邻在 KC-NES 和状态分布上存在小于 0.01 的弱增量，且转移结构无显著信号。因此，\(E_i^{near}\) 与 \(E_i^{far}\) 被成对保留：只有 near 在同等示例预算下稳定优于 far，才能说明增益来自画像匹配，而不是“多给了几个示例”。

### 4.4.2 Q7 同任务 ICL 与评测边界

在预定义的 retrieval-augmented 变体中，Q7 ICL 作为固定的同任务示例块 \(E_i^{Q7}\)。主实现为每个段落固定提供 3 条同段落示例；它们给出相同情境下其他设计者的合法 JSON、状态标注与回答，用于校准任务粒度和输出格式。任何示例都不得包含目标设计者的 Q7 文本或金标，且 Prompt 明确禁止迁移示例中的个人事实、具体方案和措辞。

Q7 ICL 改变了实验的统计含义。若示例来自与评测集完全不相交的预先划定 demonstration pool，则可视为固定任务示范；若采用 leave-one-target-out、从其余 Q7 参与者中检索，则该设置属于 retrieval-augmented transductive evaluation，而不是零样本未见情境泛化。本文分别报告两种协议：严格 inductive 设置令 \(E_i^{Q7}=\varnothing\)，只使用 Q1--Q6 条件；transductive 设置保留固定数量的 Q7 ICL，并在表题和结果中显式标注。两类结果不得合并，也不得用 transductive 结果支持 zero-shot 主张。

## 4.5 R2 Planning and Realization

### 4.5.1 Prompt 结构

阶段一 Prompt 按以下顺序组织：

```text
System: 任务定义 + 六状态本体 + 证据/事实 guard + JSON 契约
User:
  [1] 公开目标情境与当前段落任务 X*
  [2] 目标设计者 PI
  [3] 条件 C--F 的静态 Full30
  [4] 目标设计者完整 Q2 历史
  [5] 当前画像激活的冻结规则
  [6] 等量的 near 或 far Q2 示例
  [7] 固定 Q7 ICL（仅 transductive 设置）
  [8] 仅输出 state_sequence
```

Prompt 规定以下证据优先级：当前公开情境和段落任务具有最高优先级；目标设计者的 PI、V30 和个人 Q2 只用于模拟其专业语境、关注点与跨任务倾向；规则是可被场景覆盖的软优先；其他人的示例只用于过程和格式校准。任何低优先级信息都不能改写高优先级事实，也不能成为目标设计者的经历。

阶段一返回合法六状态序列后，selector 生成逐步动态 cue 表。阶段二沿用阶段一全部 chat history，加入冻结序列、静态 Full30（若启用）、逐步 cue 表和每个状态的语义定义，只输出等长 `nl_units`。语义定义明确 \(C{\to}K\) 是未来或条件式求证、\(K{\to}K\) 不产生新方案，但不强制“针对……我会……”等句式，也不根据“需要/应该”等表面词作机械判定。

### 4.5.2 推断与确定性审计

推断流程为

```text
PI + V30 + own Q2 + public target task
                    │
       frozen rule routing + near/far retrieval
                    │
       optional fixed Q7 ICL (transductive only)
                    │
      continuation 1: frozen state_sequence
                    │
 transition-aware selector: 8 cues per step
                    │
      continuation 2 in the same chat history
                    │
       aligned nl_units -> direct concatenation
                    │
 deterministic parse, validation, and audit flags
```

主实验冻结模型快照、chat template、Prompt 版本、示例池、检索距离、规则哈希、解码参数和随机种子。新条件使用同一 Qwen3-8B 快照，`temperature=0.7`、`top_p=0.9`、base seed `20260725`；同一目标跨条件使用相同阶段 seed，phase 1 与 phase 2 的 seed 分离。PP baseline 使用原有七状态 Prompt，因此 A 仅作为外部性能锚点。两阶段各只采样一次，不进行有效性拒绝采样或内容重写。

后处理只执行可形式化检查：JSON schema、字段顺序、标签集合、单元数对齐、回答长度、目标泄漏和句末标点。长度或 `CtoC` 前置条件不满足时保留原始生成并报告 compliance rate；只有 JSON/标签无法解析时才记运行失败。对“虚构已完成证据”或“\(K{\to}K\) 夹带新方案”等语义问题，不使用表面禁词过滤，而由独立人工标注或冻结 evaluator 评价。

## 4.6 Learning, Freezing, and Reproducibility

本方法不对生成语言模型进行 SFT、LoRA 或偏好优化。其适配发生在三个可复算的外部步骤：从 Q1--Q6 提取并冻结探索规则；确定性渲染静态 Full30 并逐步选择动态 8-cue；从冻结候选池检索个人、近邻、远邻和 ICL 记忆。生成器在全部条件中保持冻结，组件贡献通过输入条件消融而不是不同 checkpoint 比较。

为防止参与者泄漏，规则提取的 bootstrap、permutation 和 held-out 验证均以 participant 为重采样单位；近邻统计量只由合法检索池估计；目标参与者从所有 cross-user 示例中排除。每条生成记录保存匿名 participant key、条件名、Prompt 哈希、模型快照、规则 ID、示例 ID、原始输出、解析结果和解码参数。规则库、V30 词典、检索池与金标均以 SHA-256 固定。

正式 Q7 金标 `q7_human_gold_adjudicated_v2` 包含 162 位参与者、486 个 participant-segment pair 和 2,120 个标注单元，其 SHA-256 为 `d6e3e4b2d0f78cbb6ee3ea0e1855efacb2339bb2278ae85b47c038fd972647fa`。在 inductive 协议中，整份金标只用于生成完成后的评价，不参与 Prompt 修改、规则选择、阈值确定或解码调参。在 transductive 协议中，若从该数据的其他参与者记录构造 Q7 ICL，则必须记录每个目标对应的示例 ID，并保证目标本人的 Q7 文本和标签不进入其 Prompt；此时该金标在全局上兼具 demonstration 与 evaluation 角色，不能再称为 sealed zero-shot evaluation。

## 4.7 Research Questions and Compact Ablation

本章方法对应五个可证伪问题。

**Trajectory fidelity.** 联合生成的六状态轨迹是否接近目标设计者的 Q7 人工轨迹投影？主指标为 KC-NES，并同时报告状态分布 JS、转移二元组 F1 和长度误差，避免单一编辑相似度偏好群体高频短序列。

**Profile and value faithfulness.** 回答中的核心底线、取舍方向和显式价值主张是否与目标 V30 一致？该指标在自然语言层评价，不能由“Prompt 中出现了 V30”替代。对同一条生成回答，评价器分别以本人 V30 和固定无自映射的错配 V30 计分，得到 matched-minus-mismatched margin；这一检验不增加生成臂。

**Rule contribution.** 冻结规则是否在相同 PI、V30 和个人 Q2 条件下提高轨迹保真或价值一致性？规则带来的序列多样性本身不构成个体化证据；`D-C` 只能检验规则包是否有增量，若没有额外的 correct-route 与 shuffled-route 对照，不能进一步声称该增量具有个体特异性。

**Memory specificity.** 在示例数、格式和长度相同的情况下，V30 近邻 Q2 是否优于远邻 Q2？该比较检验的是画像匹配，而不是 ICL 的一般效应。

**Anti-collapse.** 不同画像是否被压缩为同一条高频轨迹？除 fidelity 外，报告 unique-sequence ratio、top-sequence share、参与者间序列距离，以及生成序列对画像置换的敏感度。多样性只是必要条件；随机但错误的多样化不能被解释为个体化。

考虑实验预算，主消融不采用所有模块的全因子组合，而使用如下递进/对照式设计：

|---|---:|---:|---:|---:|---:|---|---:|
| A Existing PP Baseline | ✓ | -- | -- | -- | -- | -- | -- |
| B Dynamic-profile | ✓ | ✓ | -- | ✓ | -- | -- | 3 |

Q7 ICL 在 transductive 实验中按目标排除本人后固定；对同一目标，B--F 使用完全相同的三条示例。A 为已经存在的 PI-only PP baseline，不重复生成。`B-A` 同时改变动态 V30、本人 Q2 和 Q7 ICL，只能解释为完整个体上下文包的总体差异。可作单因素解释的比较为：`C-B`（在动态 8-cue 存在时加入静态 Full30）、`D-C`（冻结规则）、`E-D` 与 `F-D`（跨用户记忆），以及 `E-F`（近邻与远邻来源）。

## 本章小结

本章将个体化设计师角色扮演形式化为同上下文两阶段条件生成：先冻结可评价的 C-K 轨迹，再依据静态 Full30 与逐步动态 8-cue 实现自然语言。方法不以固定句式制造表面合规，而把语义错位作为待评价的模型误差。PI、个人 Q2、冻结探索规则、近邻/远邻记忆和 Q7 ICL 的来源与作用边界均被显式化，从而通过 matched-vs-mismatched、near-vs-far、fidelity-vs-collapse 以及 inductive-vs-transductive 等成对比较，把“是否真正模拟了目标设计者”转化为可复现、可证伪的经验问题。
