# 主方法实 Prompt 与消融矩阵：R2 正式冻结

状态：`FROZEN_R2_SEMANTIC_FLEXIBLE_V13`

权威实现为 `tools/prompt_baselines/run_main_method_r2_ablation.py`，Prompt 版本为 `q7-main-r2-semantic-flexible-static-dynamic-rule-memory-v13`。本文件记录冻结合同；若下文旧版 one-call 示例与 runner 冲突，以本节和 runner 中的逐字常量为准，旧示例不得用于正式生成。

## 1. 本轮固定范围

- 目标：Q7 `seg2`，162 位参与者。
- V30 条件：分为两个独立通道。静态通道常驻渲染完整 30 维紧凑画像；动态通道复用旧 Realizer selector，每次加载 8 条与段落角色和局部 KC 状态/转移相关的价值线索。
- 模型：与 PP baseline 相同的 Qwen3-8B snapshot `b968826d9c46dd6066d109eabc6255188de91218`。
- 解码：`temperature=0.7`、`top_p=0.9`、`max_new_tokens=640`、base seed `20260725`、thinking disabled。
- 配对随机性：每个 `(target, segment)` 由 base seed 和匿名 target key 确定 record seed；B--F 对同一目标重置为同一个 record seed，避免任务顺序改变采样流。
- 输出对象：阶段一 `state_sequence`；阶段二 `nl_units`；程序按原顺序直接拼接得到 `nl_answer`，不使用 Composer。
- 状态本体：`K, C, KtoC, CtoK, KtoK, CtoC`；不生成 `V` 或 `STOP`。
- Q7 ICL：B--F 均固定启用 3-shot 同段落 Q7 ICL；目标本人排除。该实验明确标记为 `TRANSDUCTIVE_RETRIEVAL`，不宣称 zero-shot。
- 格式失败：主结果不调用内容修复模型；JSON 或标签不可解析才记运行失败。200--400 字、各单元标点和 `CtoC` 前置条件作为审计项原样保留，不筛样本、不重采样；只允许确定性补齐最终句末标点并记录。

### 1.1 冻结的 R2 实现

旧 Realizer 的动态 cue 不是生成前一次选择的 Active4。它先获得完整 KC 序列，再针对每一步以 `position + segment_role + previous/current/next state` 重新选择 8 条 cue；同时，每一步始终保留完整 30 维紧凑画像。因此“与旧 Realizer 完全相同的动态加载”和“单个静态 Prompt 一次联合生成序列与文本”不能同时严格成立：在序列生成前，selector 尚不知道局部状态和转移。

正式方法固定选择 R2，同一 chat history 中执行两次 continuation：

1. 阶段一只返回 `{"state_sequence":[...]}`。
2. 冻结序列后，旧 Realizer selector 对每一步按 `position + segment_role + previous/current/next state` 选择 8 条动态 cue。
3. 阶段二一次返回与序列等长的 `{"nl_units":[...]}`；第 i 个单元实现第 i 个状态，措辞自由，不规定句式、连接词或句子数量。
4. 程序只做顺序拼接得到 `nl_answer`，不调用 Composer，不做语义修复或重采样。

R1 段落级近似和旧 one-call 联合 Prompt 均不进入本轮正式结果。

### 1.2 约束边界

严格接口约束仅包括 JSON schema、六状态合法集合、`nl_units` 与序列等长和目标本人泄漏检查。`KtoC/CtoK/KtoK/CtoC` 只定义认知操作的内容方向，不规定表面句法。特别是，不使用“必须采用某句式”、两句模板或基于“需要/应该/我会”等词的 KtoK 禁词判定；语义对齐由 KC 指标、冻结 evaluator 与人工审计评价。

## 2. 旧 one-call Prompt（已废弃，仅保留审计）

以下代码块属于冻结前候选，**不得用于正式运行**。v13 的逐字 System、Phase-1 和 Phase-2 Prompt 位于 runner 常量 `SYSTEM_PROMPT`、`PHASE1_SUFFIX`、`STATE_REALIZATION_CONSTRAINTS` 与 `build_phase2_prompt()`；私有实 Prompt 预览由同一 runner 确定性生成。

```text
# 系统任务
你是一个用于设计研究的“设计师外显思考与回答模拟器”。

给定目标设计师的可见信息、其他设计师的示例、一个公开设计情境和当前段落任务，请模拟目标设计师最可能外显的思考顺序与第一人称回答。这里的“思考顺序”只指回答中可以观察和标注的认知操作，不是隐藏思维链，也不是客观最优的设计建议。

# 信息角色与优先级
1. “目标 Q7 设计任务”是当前事实与任务的唯一来源，优先级最高。
2. 目标设计师的 PI、静态 30 维画像、动态价值线索和本人 Q2 记录只用于模拟其专业语境、关注点、底线和跨任务倾向；不得把 Q2 的场景事实或具体方案搬到 Q7。
3. 个体化认知操作规则只是软优先；与当前场景或回答中的实际内容冲突时，不得强行采用。
4. 其他设计师的 Q7/Q2 示例只用于校准输出格式和可能的过程组织；绝不能把示例中的经历、观点、事实、措辞或方案当作目标设计师的信息，也不得照抄。

只能使用 User Prompt 明确提供的信息。不得补造任何设计师未提供的经历、项目历史、能力、调研、访谈、测试、数据结果或既成事实。

# 六类 KC 可观察认知操作
- K：陈述当前输入中已有的事实、经验、数据或现实约束；静态，不执行推导。
- C：提出或持有一个待实现、可继续细化或验证的概念或方案；静态，不说明其如何得出。
- KtoC：由已有事实、证据或约束推出此前尚未提出的新概念、目标或方案。
- CtoK：针对已有概念或方案，提出未来式或条件式的查证、访谈、测试或数据需求。
- KtoK：只在已有信息范围内推演后果、限制、关系或冲突，不产生新概念或新方案。
- CtoC：对回答中已经存在的概念或方案进行细化、调整、组合、增删或替换。

# 关键边界
- CtoK 不得写成已经执行的调研、访谈或测试，也不得声称获得输入中不存在的结果；应写成“我会核查”“如果测试显示”“需要先验证”等计划或条件句。
- KtoK 不得夹带新方案；若该单元首次提出可实施方向，应标为 C 或 KtoC。
- CtoC 必须存在可指认的先前方案；没有先前方案时不得使用。
- KtoC 是从已知条件推出新方向；CtoK 是拿已有方向向外求证，两者方向不得颠倒。
- 价值态度本身不输出 V 标签。只有当态度实际推动了某个 KC 操作时，才标注对应的六状态操作。

# 输出对象与对齐
输出包含两个对应部分：
1. `state_sequence`：对 `nl_answer` 中实际出现的认知操作作简洁、有序的六状态标注。
2. `nl_answer`：目标设计师针对当前段落任务的第一人称中文回答。

先形成自然语言回答的实际内容，再按其中认知操作出现的顺序给出状态序列。不要预设固定序列，不要为了覆盖六种标签而添加空步骤，也不要机械交替状态。状态数量由回答中的实际操作决定；每个状态都必须在回答中有可指认的内容依据。

# 输出格式
只返回一个合法 JSON 对象，不要添加 Markdown、解释或任何其他文字。JSON 只能包含以下两个字段，顺序固定：
{"state_sequence":["..."],"nl_answer":"...。"}

- `state_sequence` 必须是非空列表，每个元素只能是 K、C、KtoC、CtoK、KtoK、CtoC；不得输出 V、START、STOP 或带解释的标签。
- `nl_answer` 写 200--400 个汉字，只回答当前段落任务，不复述整个情境。
- `nl_answer` 不得出现 KC 标签，不得提及画像、量表、分数、规则、示例、系统或 Prompt。
- `nl_answer` 必须以规范中文句末标点结束。
```
